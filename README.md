# 听雨的声音

让泰拉瑞亚里的乐器自己演奏：选一首曲子，按下热键，游戏内的角色就会把这首曲子弹出来。

它是一个**独立的程序**，不是 tModLoader 模组。原理是把少数几处钩子注入 `Terraria.exe`，
再通过反射调用游戏自身的演奏逻辑——所以音色、音高、动画、联机同步全部走原版路径，
听不出是外部程序在弹。

> 泰拉瑞亚是 Re-Logic 的商标与版权作品。本项目与 Re-Logic 无关，也不包含游戏的任何素材或代码。

---

## 它做什么

- 曲库里有三首内置曲目，也可以扫描你指定的本地音乐目录。
- 本地音频会被转成**单乐器乐谱**（音高检测 + 节拍切分），再交给游戏演奏。
- 游戏内**手持乐器**时按热键开始接管；再按一次随时结束。
- 角色死亡、世界事件（血月、日食、沙尘暴、入侵等）会自动解除接管，不会在你没看着的时候继续弹。
- 曲子弹完自动结束接管。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows（x64 或 x86） |
| 游戏 | 泰拉瑞亚 **1.4.5.8**（Steam 版）。其它版本会被拒绝安装 |
| 运行时 | .NET Framework 4.8（Win10/11 自带） |
| XNA | XNA Framework 4.0（安装游戏时已一并装入） |

已验证的游戏版本：

```
Terraria.exe  SHA-256 960A03BFF6050CF7BE16DFC1A7B19E10FC2C4F8F835A6A3B135A50DD9E6BA2F3
```

## 安装

1. 退出游戏。
2. 解压发行包，双击 `install.ps1`（或右键「使用 PowerShell 运行」）。
3. 安装脚本会先把 `Terraria.exe` 备份到 `TingYu\Terraria.exe.orig`，再写入钩子。

如果游戏装在非默认位置，用参数指定：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -TerrariaDir "D:\Steam\steamapps\common\Terraria"
```

安装失败时脚本会停下并说明原因，不会留下改到一半的游戏。

## 使用

1. 启动游戏，进入世界，**把乐器拿在手上**（物品栏里选中也算）。
2. 按 **F10** 开始接管。再按 F10 立刻结束。
3. 曲子弹完会自动结束。

热键默认是 F10 而不是 F8：泰拉瑞亚自己的网络统计面板占用了 F8。

## 界面

`TingYu.Manager.exe` 是可选的图形管理器，用来选择曲目、指定乐器、调整移调与抖动，
并查看插件是否已连接。它和游戏进程通过两个文本文件握手：

```
<Terraria 目录>\TingYu\config.txt    管理器写入的意图（含 request=play|stop|reload|idle）
<Terraria 目录>\TingYu\status.txt    插件写入的状态
<Terraria 目录>\TingYu\tingyu.log    运行日志（GBK 编码）
```

管理器不需要一直开着：游戏只读配置，不依赖界面。

## 还原

双击 `restore.ps1`。它会从 `TingYu\Terraria.exe.orig` 还原本体、删掉复制进游戏目录的两个 DLL
并移除数据目录，`Terraria.exe` 会逐字节回到原版（可用哈希核对：`960A03BF…`）。

## 从源码构建

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Configuration Release -Package
```

产物在 `build\Release\payload\`（载荷目录）与 `build\Release\TingYu-Release.zip`（发行包）。

依赖：Visual Studio 2022（含 .NET 桌面开发工作负载）、.NET Framework 4.8、XNA 4.0。

### 目录结构

```
src\TingYu.Core      乐谱模型、音高换算、内置曲目、音频转录（不引用游戏）
src\TingYu.Plugin    注入进游戏的接管层；通过反射调用游戏成员，本身不引用游戏程序集
src\TingYu.Patcher   注入与还原的打包工具（Mono.Cecil）
src\TingYu.Manager   可选的图形管理器（WinForms 自绘界面）
tools\               构建、部署、测试与读日志脚本
```

## 已知限制

这些是**设计上的取舍**，不是待修的缺陷：

- **只取一条旋律线。** 和弦密集的音频会被简化成最响的那条旋律，伴奏会丢失。
- **吉他和弦只有 6 档，音高必然变粗。** 常春藤、雨歌、星星吉他由「到鼠标的距离」决定，
  只有 6 个固定和弦（`Am – G – Bm – C – D – Em`），不像竖琴那样有 13 级。
  这 6 个和弦的音程正好铺满 C 大调音阶，所以**任何 C 大调旋律都不可能被它们忠实表达**——
  这是乐器的固有上限。既然无法忠实，就选「音高变化听得出来」这一头：
  乐谱音域被均匀铺到 6 个和弦上，最低音给最低档、最高音给最高档。
  内置三首曲子都能用满 6 档，听感上是一条有起伏的和弦进行，而不是两三个和弦反复。
- **只支持单乐器。** 谱面是单声部，不会同时指挥多件乐器。
- **竖琴类音高精度是 13 级。** 游戏内部把音高量化成 ±6 级（步长 1/6），
  对应两个八度、每级一个全音；半音阶上更细的微分音无法表现。
  实测内置三首曲子各用到 5~7 级——这是旋律自身的宽度决定的，不是档位不够。
- **音频转录是估计。** 内置曲目的音高是精确的（记谱在源码里），本地音频转录出来的
  音符会有误差，速度快的段落更容易出错。

## 说明书之外的两件事

**为什么必须注入而不是做模组。** tModLoader 的版本长期落后于游戏本体，而本程序要用的
演奏逻辑就在本体里。注入让程序直接作用于当前版本，代价是需要针对具体游戏版本验证。

**为什么安装要校验版本。** 注入点由 IL 结构定位。游戏版本一变，定位可能落在错误的指令上，
后果是游戏启动即崩。所以安装前会比对哈希，版本不符就拒绝写入。
